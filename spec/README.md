# Spec status

One line per spec folder: what it covers and where it stands. Each folder has `requirements.md`, `design.md` and `NEXT_PROMPT.md` (see "Specs" in `CLAUDE.md`). Update the line here when a spec changes status.

- `cost-per-line/`: press counts, uses per button and feasibility, for when the solver knows the puzzle's buttons and limits. Requirements only; design and next prompt deferred.
- `division-shortcut/`: string edits plus whole-number division (`X ÷ D = q`, then edit q into G) for early-game Engineering Calculator buttons. Implemented (v1: early-game buttons, divisor built from `10` only). Works but `Solve` lags; speeding it up is a future ticket.
- `digit-keys/`: single digit keys `0`–`9` in the Buttons box and as Division Shortcut divisors, plus two UI changes (lines show only presses and the count; no search at startup). Implemented. With all buttons, `Solve` takes about 10–30% longer than before (41 → 483: 12 s to 14 s, Debug).
- `digit-keys-right-side-only/`: bugfix. Digit keys (`10` and `0`–`9`) work on the right side only; the simulator, `LeftEdits` and the Division Shortcut wrongly let them edit the left side. Implemented.
- `streaming-results/`: run the Division Shortcut search in the background, show lines as they're found (kept sorted), Esc stops it, Enter restarts it. Complete (`DivisionShortcut.Search` + `Ranking`; `Solve` wraps `Search`; `MainForm` uses a background task, a queue and a 100 ms timer).
- `parallel-search/`: run the Division Shortcut on half the logical processors, each worker thread pinned to one of the last N processors, with the same results. Needs streaming-results (done). Complete. Enter runs the pinned parallel search only (the 1-thread benchmark was removed). 41 → 483, Release, 9950X3D: about 8.3 s single vs 5.1 s parallel (see the design's "As built").
- `game-state-scan/`: the mod publishes each new puzzle (identified by round and goal) to `puzzle.json` after the game settles (flags clear, 50 ms with no change). The app follows it: it fills in S, G and the buttons with charges (`X1:2` syntax), runs the Division Shortcut, and rejects lines that need more presses than a button's charges. One solve per puzzle; presses and purchases don't re-trigger. Complete (2026-10-22), plus a Lock checkbox.
- `modulo-in-results/` (complete, 2026-10-22): once the Division Shortcut finishes, search Modulo Shortcut lines (every factor pair, both formulas, A = 1..99, all k) with cost ≤ best cost so far + 2 (arithmetic and division; was division + 1), up to 100, and merge them into the Lines box ranked by cost, then drained (buttons left at 0, fewest first), then spare (sum of the charges of the distinct buttons used). Every button must have a charge count. Needs `mod` in the simulator. Also runs when the Division Shortcut can't (no `÷`), with cap 12. Status line: `N division line(s), M modulo line(s), R rejected`. The manual A, k, dropdown and Solution rows are gone from the UI.
- `traditional-operators/`: `+`, `-`, `×` (game ids `operator+`, `operator-`, `operator*`). One operation per `=`; `-` below 0 gives 0. New `ArithmeticSearch`: one-operator lines (edit S into X, op, D = Y − X / X − Y / Y ÷ X, `=`, edit Y into G) and edits-only lines, run before the Division Shortcut. Complete (2026-10-22); the division search is capped at the cheapest arithmetic cost + 2, and the modulo search at the best line + 2. Multi-operator lines, `number_charge` and the other unmapped buttons are follow-ups.
- `left-transforms/` (complete, 2026-10-23; arithmetic phase only, division and modulo unchanged; 41 → 483 with every button about 0.9 s Release): left-side buttons that change the value in one press: `X++`, `X--`, `X+k`, `X-k`, `X*2`, `X/2`, `<<`, `>>`, `sqr`, `sqrt`, digit maps `a->b`, `to25`, `round`. A transform catalogue (buttons as data), the simulator, parse and game ids, and a new `LeftSearch` (forward/backward BFS over displays, meet in the middle) used by the arithmetic phase. Division and modulo unchanged. `operator_last` and number keys `11`, `15`, `32`, `99` are separate follow-ups.
- `glass-buttons/` (complete, 2026-10-23): the mod adds `glass` and `legendary` to each button in `puzzle.json` / `state.json`, still reporting raw `uses`. `GameLink.Parse` clamps a glass button's charge to `min(uses, 1)` (glass breaks after one press and `SubUse` doesn't lower `uses` for it); `GamePuzzle.Glass` lists the glass tokens (not shown in the status, to keep it short). Tested in-game with `sqr`.
- `leading-zeros-flip-and-prepend/` (bugfix, complete, 2026-10-24): in the game `flip` and `dX` read the left side as a number, so leading zeros drop (`120` `flip` → `21`, `04` `1X` → `14`); `Xd` and digit maps edit the text and keep them. Fixes the simulator, `LeftSearch`, `LeftEdits`; Modulo lines padded with `0X` go away (`flip X0 … flip` padding stays). `EngineeringCalculator.Prepend` / `Flip` hold the rule. Follow-ups: the 6-character display limit and the 999 999 cap (now `display-cap/`).
